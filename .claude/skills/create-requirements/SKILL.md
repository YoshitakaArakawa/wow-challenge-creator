# WOW要件作成スキル

出題ページに載る文章（Introduction・Requirements・Dataset）を作る。書き方の規範は [wow-style-guide.md](wow-style-guide.md) にあり、書く前に必ず読む。

要件文は 2 回に分けて書く。参加者に見せる版は、ワークブックが完成してから確定する。何が画像から読めて何を文章で補うべきかは、完成した表示が決めるため。

| 場面 | いつ | 読み手 | 書き方 |
|---|---|---|---|
| ドラフト | `create-workbook` の前 | `create-workbook` とユーザー | 仕様を網羅する。体裁は問わない |
| 確定 | `create-workbook` の refine ループが終わった後 | WOW の参加者 | スタイルガイドに従って削る |

出題フォルダに `refine/render/` の描画があれば確定、なければドラフトから始める。ユーザーが手動でワークブックを作った場合は、そのスクリーンショットをもらって確定に進む。

## ドラフト

1. 前提を確認する
   - 出題フォルダ `outputs/YYYY-MM-DD-theme-name/` があるか
   - テーマ・難易度・使用機能・データセットが決まっているか（未決定なら `brainstorm` に戻す）
   - 既存Vizを参考にする場合は、先に `analyze-twbx` で解析する
2. 必要ならプロトタイプ HTML を作る（下の「プロトタイプHTML」）
3. `requirements-ja.md` と `requirements-en.md` に作業用の要件を書く。定義・判定ルール・パラメータ・表示要素を漏れなく書く。Introduction は仮でよい
4. 出題意図を `discussion.md` の「出題意図」節に書き留める。確定時の Introduction の素材になる
   - なぜ今このテーマか、作者自身の考え
   - きっかけになった出来事と、その一次資料（ユーザーのメモ・書き起こし）の所在
   - ユーザーの言い回しは、整えずにそのまま残す

## 確定

1. 完成した表示を読む。`refine/render/` のダッシュボード描画（なければユーザーのスクリーンショット）を開く
2. ドラフトの要件を 1 行ずつ描画と照らす
   - 画像から読める行は削る
   - 画像から読めない定義・ルールは残す
   - refine ループで消えた・変わった要素を反映する
   - 値や境界の扱いは、ワークブックの実装に合わせる
3. `discussion.md` の「出題意図」から Introduction を書く
4. 日本語版でユーザーと合意する
5. 合意後に英語版を作る。直訳ではなく、WOW コミュニティのトーンに合わせる。末尾に HTML 版を埋め込む
6. 参加者視点のレビューを受ける（下の「参加者視点のレビュー」）
7. 指摘を反映し、ja・en・HTML 版の3つが同じ内容になっているか確かめる

## 参加者視点のレビュー

作成中のセッションは文脈を知りすぎていて、説明の抜けに気づけない。Agent ツールで新しいコンテキストのサブエージェントを 1 体起こして読ませる。

- 渡すのは `requirements-en.md` とダッシュボード描画のパスだけ。会話の経緯や意図は伝えない
- 次の 3 点を報告させる
  - 定義が曖昧で、実装が一意に決まらない要件
  - 説明なしに使われている用語や前提
  - Introduction の AI 生成感（スタイルガイドの「避けるべきこと」に照らす）
- 指摘を採るかどうかは、ユーザーと決める

## プロトタイプHTML

Vizのレイアウト・線の本数・色分け・BAN配置などを事前に視覚化したい場合に作る。「プロトを作って」「イメージを見たい」と言われた時、または認識合わせが必要そうな時に提案する。

- 出題フォルダの `prototype/` に保存する（例: `prototype/prototype.html`。案が複数なら `prototype-weekly.html` のように並べる）
- `prototype/` は Git 追跡外。`create-workbook` の比較ページがこのフォルダの HTML を一覧する
- ファイル単体で開けるよう、先頭に `<meta charset="utf-8">` を置く
- 作ったら、開くコマンドをチャットに出してユーザーに見てもらう（出し方はリポジトリの CLAUDE.md「ユーザーに開いてもらうもの」）
- Chart.js / vanilla HTML / SVG など軽量な手段で実装する
- 合意する前に、表示要素を 1 つずつ見て、他の要素から読める情報を繰り返していないか確かめる。プロトタイプに入った要素は、要件文とワークブックにそのまま引き継がれる

## 成果物

| ファイル | 説明 |
|---|---|
| `outputs/{theme}/requirements-ja.md` | 日本語版（先に合意する） |
| `outputs/{theme}/requirements-en.md` | 英語版 + 末尾にHTMLコメント埋め込み |
| `outputs/{theme}/discussion.md` の「出題意図」節 | ドラフト時に追記。確定時の Introduction の素材 |
| `outputs/{theme}/prototype/*.html` | 任意。Vizイメージの事前可視化 |

ドラフトの要件は `create-workbook` の入力になり、確定した要件は `create-x-post` の入力になる。
