# ダッシュボードのデザイン判断

## 目次
- 明るさの 3 段
- 色の使い方
- 見せ場は 1 か所
- 線とマーク
- 出題の見本の状態
- 案の出し方と決め方

## 明るさの 3 段

画面が「グレーすぎてメリハリがない」ときの原因は、彩度より明るさの段階の無さであることが多い。要素を役割で 3 段に分け、明るさで差を付ける。

| 段 | 要素 | 値の例 |
|---|---|---|
| 背景 | 比較の棒、前年の線、範囲の帯、区切り線 | 棒 `#cdd1d6`、前年の線 `#d6d9de`、帯 `#f1f4f7` |
| 主役 | 今年の線、KPI の数値 | 線 `#676f7a`、数値はインク `#1d1f24` |
| 信号 | 状態の色（良い・悪い・範囲外） | `#2063b0` / `#a6c0e1` / `#e4a59f` / `#a83634` |

- 背景を一段明るくすると、主役や信号の彩度を上げなくても目立つ。全体を濃くしたり、彩度を上げたりする前に試す。
- 平均線のような補助線は主役より一段淡くする（例：`#9a9fa6`）。同じ濃さだと主役と競う。

## 色の使い方

状態を色で示すダッシュボードでの規範。色でカテゴリを見分けることが主題の出題では、1 項目めは適用しない。

- 色は意味（状態）にだけ使う。主役の線も色にせず、無彩色の濃さで示す。色が状態だけに付いていれば、色を見るだけで状態を読める。
- グレーは暖色系か寒色系の 1 系統にそろえる。暖かいグレーの棒と青みのグレーの線が混ざると、まとまりが崩れる。
- 発散型の状態色は、内側（範囲内）の 2 色を淡く、外側（範囲外）の 2 色を濃くする。内側の淡い色は彩度を上げすぎない（ピンクと水色の組は子どもっぽく見える）。
- 色の意味は記号（▲ ▼）と一緒に出す。チェック・バツ（✓ ✕）は Yes / No の文字と重複するなら外す。

## 見せ場は 1 か所

- ダッシュボードの仕事（例：「今週はどうだったか」に答える）を担う部分を見せ場にする。見せ場にだけ淡い背景のパネルなどを付け、他は静かにする。
- 見せ場の中では、強い色が「注目すべきもの」と一致するようにする（範囲外のタイルだけ濃い）。
- 区切り線や凡例などの構造物は、内容の事実（まとまりの境目、線の意味）を表すときだけ置く。

## 線とマーク

- 主役の線は、濃くして細くする。太い中間色の線は「強すぎる」と感じられやすい。
- 比較の線は主役の後ろに描く（色の凡例の順。twb-pitfalls.md）。
- 強調点（最新週の円）は、線と同じ色の枠を付けると輪郭が締まる。大きさは線の太さに合わせて控えめにする。
- 線や帯の意味は、段の見出しの下に 1 行の凡例で書く（線・点線・帯の見本と短い名前）。凡例を全部消すと、平均線や帯が何かを読み手が推測することになる。

## 出題の見本の状態

- 既定のパラメータ値（週など）は、すべての候補について判定を計算し、ダッシュボードの仕掛けが見える値を選ぶ。範囲外が 0 件の週では、記号も濃い色も大見出しの文も出ない。
- 状態が混ざる週（例：売上は普段どおり、利益だけ範囲外）は読みどころがあり、見本に向く。

## 案の出し方と決め方

1. 現状の弱点を先に言葉にする（何がメリハリを奪っているか）。
2. TWB より先に、ドラフト HTML（`refine.html`）に 2〜3 案を作る。値はトークン（CSS 変数）にまとめ、案ごとに上書きする。
3. 案は切り替えボタンと URL のハッシュ（`refine.html#a`）の両方で切り替えられるようにし、ヘッドレス Chrome で全案を撮影して見比べる（`chrome --headless --screenshot=<保存先.png> --window-size=<幅>,<高さ> <refine.html の file URL>#a`。保存先は `refine/`。PNG は gitignore 済み）。
4. 各案の弱点と Tableau での手間（色の差し替えだけか、計算やシートが増えるか）を添えて、推奨を 1 つ示す。
5. 採用した案は HTML の既定にして切り替えを外し、TWB に入れる。その後の微調整（線を弱める、点を小さくする）は TWB で直接回す。
