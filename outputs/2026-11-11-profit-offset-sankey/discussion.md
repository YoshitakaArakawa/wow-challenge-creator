## ヒアリング

### コンセプト（ユーザー提示の画像から）
負の値（損失）を扱う Sankey Diagram。Superstore の利益を次の3段で流す。

1. 上段: 全体の利益（青）と相殺（オレンジの斜線）
2. 中段: カテゴリ（家電・事務用品・家具）ごとの利益
3. 下段: カテゴリごとに「稼いだ」（正の利益の合計）と「失った」（負の利益の合計）

カテゴリをタップするとドリルダウンする。モバイル縦長レイアウト。

### 確定
- 難易度: 上級
- データ: Sample Superstore

### 画像の数値（帳尻の確認）
| カテゴリ | 稼いだ | 失った | 差（利益） |
|---|---|---|---|
| 家電 | +$185K | −$39K | $147K |
| 事務用品 | +$183K | −$57K | $126K |
| 家具 | +$81K | −$62K | $20K |
| 合計 | +$449K | −$158K | ≈ $292K |

上段の「利益 $292K（青）＋相殺 −$157K（斜線）」の幅は、稼いだ総額 $449K に相当する。帯の幅はすべて正の値で表し、負の分は相殺として別の帯にしている。

## 設計の核
Sankey の帯は負の幅を持てない。純利益だけで流すと、赤字の明細が利益を食っている事実が消える。そこで純利益を「稼いだ（総額）」と「失った（総額）」に分け、差を相殺として可視化する。この発想の転換が出題の主題になる。

## 技術的ポイント（WOW としての学習価値）
- 明細を正負で分け、総額と純額の両方を計算する（行レベルの IF と集計、または LOD）
- 3段のノード位置と帯の開始・終了位置を累積で計算する（テーブル計算または LOD）
- データ密度化 + シグモイド曲線で帯を描く
- 相殺の帯を、正の帯と同じ座標系に積む
- カテゴリ選択でサブカテゴリへ展開するドリルダウン（パラメータアクションまたはセットアクション）

## 未確定（要件ドラフトで決める）
- **「失った」の集計粒度**: 家具の −$62K は、サブカテゴリ単位の赤字（約 −$21K）よりかなり大きい。このため画像は明細行（または注文）単位で正負を分けていると推測する。粒度で答えが大きく変わるため、要件に明記する
- **データセットの版**: 画像の全体利益は $292K。従来版の Superstore は約 $286K（記憶ベース、未確認）。WOW 公式リポジトリの Sample - Superstore-2026.xlsx で再集計して確定する
- **ドリルダウンの範囲**: カテゴリ → サブカテゴリの同構造展開を想定（推測）。展開後も「稼いだ / 失った」を出すか
- **斜線の表現**: Tableau に標準の塗りパターンはない。shape・画像・細い線の重ね描きなどの代替を検討する
- **ワークブックの作り方**: `create-workbook` は Sankey を対象外としている。手作業寄りで作るか、範囲外を承知で個別に対応するかを決める

## 2026-11-08 追記: 作り方の調査

### ユーザーからのフィードバック
- データセットは何でもよい（後で差し替えられる）
- 「利益が正か負かのディメンションを用意するだけでよいか」を確認したい

### 結論
正負のディメンションは必要だが、それだけでは画像の形にならない。

- 正負ディメンションを Level に置き、ABS(Profit) を帯の幅にすると、カテゴリのノード幅は「稼いだ + 失った」（取引の総量）になる。純利益は出ない
- 画像の帯は、通常の Sankey の保存則（ノードに入る量 = 出る量）を満たしていない
  - 上→中: 利益（純額）と相殺（損失額）が入る。ノード幅は 純額 + 損失 = 稼いだ
  - 中→下: 稼いだ全体が「稼いだ」へ、斜線部分から「失った」へ出る。斜線部分（損失額）を二重に使っている
- このため、Level と Link を指定するだけの Sankey 拡張機能では描けない。帯ごとに始点・終点の位置を計算する手組みの Sankey（データ密度化 + シグモイド）が要る

### 手組みに必要なもの
- 行レベルの正負ディメンション（集計粒度の決定を含む）
- カテゴリごとの 稼いだ・失った・純額
- 帯の種類 4 つ（上→中の純額・相殺、中→下の稼いだ・失った）× カテゴリ数 の scaffold
- 各帯の始点・終点を、ノード内の累積で計算する（LOD またはテーブル計算）

### 新たに見つかった論点: 純額が負になるノード
「純額 + 相殺 = 稼いだ」の形は、純額が正であることを前提にしている。サブカテゴリへドリルダウンすると、赤字のサブカテゴリ（従来版 Superstore では Tables・Bookcases・Supplies、記憶ベース・未確認）で純額の帯が負の幅になる。ドリルダウンを入れるなら、このときの描き方を決める必要がある。

### 代替案: 保存則を満たす向き
流れを「稼いだ → カテゴリ → 純利益（合流）/ 失った（流出）」にすると、すべての帯が正の幅で保存則も満たす。ただし、ここでも純額が負のノードは同じ問題を抱える。

### 調査の出典
- 第三者の Sankey 拡張機能（ShowMeMore）は、0 以下の値でチャートが壊れうると明記: https://docs.infotopics.com/showmemore/troubleshot/sankey-diagram-crashes-or-fails-to-load
- 公式 Sankey 拡張機能は Level（ディメンション 2〜5 個）と Link（メジャー）を指定する形式。負の値の扱いは記載なし: https://exchange.tableau.com/en-GB/products/932
- 他ツールでも、負の値は帯が出ない・絶対値で描かれる: https://docs.inforiver.com/analytics+/quick-charts/storytelling-charts/sankey-charts

## 2026-11-12 追記: 完成までの決定

### 確定した表現
- 左から 3 段: Net Profit の棒 → Gains / Loss → Category
- 明細行の Profit が 0 以上なら Gains、負なら Loss（0 は Gains 側）
- 帯の太さは、利益の絶対値の総額（Gains + Loss）を 1 とした割合。縦軸は全シートで 0〜1 に固定
- 左端は Net Profit のガントバー 1 本。Gains と Loss の小さいほうの上端から、大きいほうの上端までを塗る（長さ = 純額の絶対値）。色は純額の正負
- 帯は左端で Net の棒に収束する（B 案）。大きいほうの Sign は純額の幅まで細くなり、小さいほうの Sign は一点にすぼまる。一点は、Loss なら Net の棒の下端、Gains なら上端に来る（帯が交差しない）
- 中央は下に Loss、上に Gains。右端はカテゴリを純額の大きい順に上から並べ、カテゴリ内は上に Gains、下に Loss。カテゴリの棒はカテゴリの純額の正負で色分け
- Ship Mode と Region のフィルターを全シートに適用。計算は表計算と行レベルの計算だけで組み、LOD は使わない（フィルターの設定を増やさないため）
- ダッシュボードは 1000 x 800、6 種のシートを横に並べる（参考ワークブックと同じ作り）
- タイトル: #WOW2026 W47: Let's Build a Converging Sankey!

### 不採用にした案
- A 案（帯が Net の棒の底から重なる）: 計算はより単純だが、帯が Net の棒より下にも伸び、棒と帯の関係が弱い
- Waterfall: Loss の置き場所が Waterfall とサンキーで 2 つに割れ、純額が負のときに帯の出どころが棒と合わない
- 相殺分を斜線やグレーで描く: Tableau に塗りパターンがない。相殺は帯の収束が表すので不要になった

### 2026-11-12 夕方の変更: 4 段構成と配色
- 右端の後ろにもう 1 段サンキーを足し、4 段にする: Net Profit → Gains / Loss → カテゴリごとの Gains / Loss → カテゴリごとの Net Profit
- 4 段目は、1 段目と同じルールで帯がカテゴリの純額の棒に収束する（両方の帯が小さいほうの分だけ細くなり、小さいほうは一点。Loss の一点は棒の下端、Gains の一点は上端）
- 4 段目の純額の棒は、カテゴリの区画（Gains + Loss）の中で、小さいほうの高さから大きいほうの高さまでを塗る
- 棒は濃い色、帯は同じ色相の淡い色（不透明度ではなく色の濃さで分ける）。2・3 段目のラベルは棒の中に白字
- 配色は「今の色の濃淡」: Gains の棒 #1B6FB0・帯 #8CC8F5、Loss の棒 #C46D0E・帯 #F9C487（今のワークブックの #2D9CED / #F59623 を基準に明るさを変えた値。Tableau 標準パレットの色ではない）
- 参加者への制約として「LOD を使わない」は入れない
- プロトタイプ: prototype/sankey-four-stage-v2.html

整理（Introduction の素材）:
